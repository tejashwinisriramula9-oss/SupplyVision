### For AI Assistant Handoff | Last Updated: July 2026

## 1. Project Name & Objective

**Name:** SupplyVision  
**Subtitle:** Enterprise Supply Chain Analytics & Inventory Intelligence Platform  
**Objective:** Transform raw supply chain data into actionable business intelligence through a full end-to-end data analytics solution — covering data ingestion, ETL, a Python analytics engine, a REST API, forecasting models, automated reports, and Power BI dashboards with DAX-based KPIs.

**Target users:**
- CEO / COO / Operations Directors → Executive dashboards, KPI cards, revenue visibility
- Supply Chain Managers → Inventory monitoring, demand planning, supplier tracking
- Data Analysts → Data exploration, KPI reporting, forecasting, business recommendations

---

## 2. Problem Statement

Large organisations struggle to get a unified, real-time view of their supply chain operations. Data is spread across Excel/CSV files, ERP systems, and logistics platforms with no single source of truth. This project solves:

- No centralised analytics layer for inventory, orders, suppliers, logistics
- No demand forecasting to anticipate stock-outs or overstocking
- No automated reporting for executives or operations managers
- No Power BI–ready data model with proper relationships and DAX KPIs

### Table Definitions

**dim_suppliers** (50 rows)
- `Supplier_ID` PK, `Supplier_Name`, `Country`, `Region`, `Lead_Time` SMALLINT
- `Reliability_Score` DECIMAL(5,4) [0–1], `Reliability_Tier` ENUM('Poor','Acceptable','Good','Excellent')
- `Lead_Time_Category` ENUM('Express','Standard','Extended','Long Lead')
- `Supplier_Cost` DECIMAL(14,2), `Contact_Email`, `Phone`, `Is_Active`
- Indexes on `Reliability_Tier`, `Region`, `Is_Active`

**dim_customers** (800 rows)
- `Customer_ID` PK VARCHAR(12), `Customer_Name`, `Company`, `Email`, `Phone`
- `Country`, `Region`, `Customer_Segment` ENUM('Enterprise','Mid-Market','SMB','Government')
- `Registration_Date` DATE, `Is_Active`

**dim_products** (200 rows)
- `Product_ID` PK VARCHAR(10), `Product_Name`, `Category` (10 categories), `Sub_Category`
- `SKU` GENERATED ALWAYS AS (Product_ID) STORED
- `Safety_Stock`, `Reorder_Point`, `Min_Order_Qty` INT
- `Unit_Cost`, `Unit_Price` DECIMAL(12,2)
- `Margin_Pct` DECIMAL(6,2) GENERATED ALWAYS AS ((Unit_Price-Unit_Cost)/Unit_Price*100) STORED
- `Supplier_ID` FK → dim_suppliers
- CHECK: Unit_Price >= Unit_Cost, Safety_Stock >= 0, Reorder_Point >= Safety_Stock

**fact_inventory** (200 rows, one per product)
- `Product_ID` PK FK → dim_products, `Current_Stock` INT, `Inventory_Value` DECIMAL(16,2)
- `Stock_Status` ENUM('Out of Stock','Low Stock','Optimal','Overstock')
- `Last_Updated` DATE, `Snapshot_Date` DATE DEFAULT CURRENT_DATE

**fact_orders** (5,000 rows)
- `Order_ID` PK VARCHAR(12), `Product_ID` FK, `Customer_ID` FK, `Order_Date` DATE
- Full date hierarchy: `Year`, `Month`, `Quarter`, `YearMonth`, `YearQuarter`, `WeekOfYear`, `DayOfWeek`
- `Quantity` INT, `Unit_Price`, `Discount` DECIMAL(5,4), `Revenue`, `COGS`, `Gross_Profit`, `Gross_Margin_Pct`
- `Order_Status` ENUM('Delivered','Shipped','Processing','Cancelled','Returned')
- `Sales_Channel` ENUM('Online','Direct Sales','Partner','Distribution')
- `Category`, `Warehouse_ID` FK, `Supplier_ID` FK
- Logistics denormalised: `Shipment_Count`, `Avg_Transit_Time`, `Total_Transport_Cost`, `Delayed_Shipments`
- 8 indexes covering common filter/group-by patterns

**fact_logistics** (4,500 rows)
- `Shipment_ID` PK VARCHAR(12), `Order_ID`, `Supplier_ID` FK
- `Ship_Date`, `Delivery_Date` DATE, `Expected_Transit_Days`, `Transit_Time`, `Delay_Days` SMALLINT
- `Is_Delayed` TINYINT(1), `Transport_Cost`, `Cost_Per_KG`
- `Carrier` VARCHAR(60), `Delivery_Status` ENUM('On Time','Delayed','Lost','Returned')
- `Origin_Country`, `Destination_Country`, `Weight_KG`
- Full date hierarchy: `Ship_Year`, `Ship_Month`, `Ship_Quarter`, `Ship_YearMonth`
- 6 indexes

**audit_inventory_history** (auto-populated by trigger)
- `History_ID` AUTO_INCREMENT PK, `Product_ID`, `Change_Date`, `Old_Stock`, `New_Stock`, `Change_Reason`, `Changed_By`

### MySQL Views (5)
- `vw_executive_summary` — revenue + margin by Year/Quarter/YearMonth
- `vw_inventory_intelligence` — products joined with stock and supplier
- `vw_logistics_performance` — shipments joined with suppliers and orders
- `vw_supplier_scorecard` — suppliers with aggregated shipment metrics

**Base URL:** `http://127.0.0.1:8000`  
**Docs:** `http://127.0.0.1:8000/docs` (Swagger UI)

### KPI Engine (src/analytics/kpi_engine.py)

Class `KPIEngine` accepts 5 DataFrames at construction:
- `executive_kpis()` → `ExecutiveKPIs` dataclass
- `inventory_kpis()` → `InventoryKPIs` dataclass
- `logistics_kpis()` → `LogisticsKPIs` dataclass
- `supplier_kpis()` → `SupplierKPIs` dataclass
- `revenue_trend(freq)` → DataFrame
- `top_products(n)` → DataFrame
- `carrier_performance()` → DataFrame
- `supplier_comparison()` → DataFrame
- `inventory_by_category()` → DataFrame
- `product_velocity(n)` → DataFrame (with Movement_Class: Dead/Slow/Normal/Fast)
- `all_kpis()` → dict of all 4 domains

### Forecasting (src/forecasting/demand_forecast.py)

- `LinearDemandForecaster` — scikit-learn LinearRegression with lag features (lag_1, lag_2, rolling_3), seasonal encoding (sin/cos), StandardScaler. Evaluates MAE, RMSE, R², MAPE on 20% hold-out.
- `TimeSeriesForecaster` — statsmodels Holt-Winters ExponentialSmoothing with additive trend/seasonal. Falls back to SARIMAX(1,1,1)(0,1,1,12) if Holt-Winters fails.
- `run_forecasting(orders, horizon_months)` — runs both models, averages into Ensemble, projects inventory requirements (Safety_Stock_Required = daily_demand × lead_time × 1.5), saves 4 CSVs to `data/exports/`.
- Forecast endpoint caches results in `_forecast_cache` dict (keyed by horizon_months).

### Report Generator (src/reports/report_generator.py)

`ReportBuilder` class takes 5 DataFrames + optional fact_orders:
- `monthly_report(year, month)` → JSON with KPIs, top 5 products, carrier performance
- `quarterly_report(year, quarter)` → JSON with revenue, gross profit, all KPI domains
- `kpi_report()` → JSON with all 5 domains
- `executive_summary(year)` → JSON with headline KPIs, revenue trend, top products, + AI recommendations
- `_generate_recommendations()` — rule-based business recommendations (stock-out > 10%, OTD < 85%, etc.)
- `export_all(year)` → writes 18 JSON files to `reports/`

## 11. Coding Standards & Architecture Decisions

- **Language standard:** Python 3.11 with type hints throughout
- **Architecture:** Clean layered architecture — Ingestion → ETL → Analytics → API → Presentation
- **Data pattern:** Star schema in MySQL; Parquet for analytical layer; in-memory DataFrames for API
- **API design:** RESTful, versioned (`/api/v1/`), JSON responses, query param filtering
- **KPI calculations:** All done in Python (`KPIEngine`) not in SQL — keeps logic testable and DB-agnostic
- **DataFrame cache:** All 6 DataFrames loaded once at startup, shared across all request handlers via module-level dict — avoids per-request file I/O
- **Forecasting cache:** Forecast results cached in `_forecast_cache` dict per horizon to avoid re-running ML on every API call
- **Error handling:** All ETL functions return cleaned DataFrames (never raise on data issues — use clip/fillna/dropna). API returns 503 for missing data, 404 for unknown IDs.
- **Logging:** Loguru throughout — console (INFO) + file (DEBUG) with rotation
- **Testing:** Pytest with fixtures. Data-driven tests using synthetic mini-DataFrames (not the real 5000-row dataset).
- **SQL style:** All FK constraints named (`fk_*`), all indexes named (`idx_*`), all tables commented
- **File outputs:** All data files go to `data/raw/`, `data/processed/`, `data/exports/`. Reports go to `reports/`. SQL goes to `sql/`. Logs go to `logs/`.
- **No hardcoded credentials:** All DB config from `.env` via python-dotenv
- **Seed for reproducibility:** `np.random.default_rng(seed=42)` and `random.seed(42)` in generator
